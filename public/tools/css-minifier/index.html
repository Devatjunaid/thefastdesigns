About this css minifier & beautifier

Minification removes comments, whitespace and redundant characters such as the final semicolon in a rule and leading zeros (0.5 → .5). It doesn’t change how the CSS works. Typical stylesheets shrink by 15–30% before compression; with gzip or Brotli on top, the transfer size drops much further.

Strings (like content: "…" and quoted URLs) are protected during processing, and comments starting with /*! are kept because they usually carry license notices. For complex builds, a build tool such as Lightning CSS, cssnano or esbuild can also merge rules and rewrite values.

Tips and best practices

  • Keep the readable source file in your project and only ship the minified version.
  • Serve CSS with Brotli or gzip compression; it usually saves more than minification alone.
  • Use Beautify to inspect minified CSS from a third-party theme before editing it.
  • Remove unused CSS first; deleting dead rules saves far more than squeezing whitespace.
  • Inline only the critical CSS for above-the-fold content and load the rest normally.

Frequently asked questions

Does minifying CSS change how it works?

No. It only removes characters the browser doesn’t need, such as comments and whitespace.

How much smaller will my CSS be?

Usually 15–30% before gzip or Brotli. Heavily commented files can shrink more.
