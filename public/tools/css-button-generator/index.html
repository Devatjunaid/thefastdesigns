About this css button generator
A good button has enough padding to be an easy target, clear contrast between text and background, a visible hover state and a visible keyboard focus state. The generated CSS includes all of these, plus a short transition so state changes don’t feel abrupt.
The same class works on <button> and <a> elements. Use a button for actions (submit, open) and a link for navigation.


Tips and best practices
  • Aim for a minimum target size of 24×24px (WCAG 2.2 AA) and ideally 44×44px for touch screens.
  • Check the label against the background with the contrast checker; 4.5:1 is the safe target for normal-size text.
  • Keep the focus-visible outline: removing it makes your site hard to use with a keyboard.
  • Use one primary button style per screen and a quieter secondary style for other actions.
  • Write labels as verbs that describe the result, like “Download invoice”, not “Click here”.

Frequently asked questions
Should I use <button> or <a> for buttons?
Use <button> for actions on the page and <a> for links that navigate to another URL. The CSS works on both.
How big should a button be?
At least 24×24px to meet WCAG 2.2 AA, and around 44×44px is recommended for touch devices.
