About this viewport unit converter

1vw equals 1% of the viewport width and 1vh equals 1% of the viewport height. So 5vw is 19.5px on a 390px-wide phone but 96px on a 1920px desktop: that 5× difference is why pure vw font sizes are usually wrapped in clamp() with a minimum and maximum.

On mobile, 100vh includes the area behind the browser’s address bar, which can make full-height sections overflow. The newer svh, lvh and dvh units (small, large and dynamic viewport height) fix this and are supported in all modern browsers.

Worked example

5vw is 19.5px on a 390px-wide phone but 72px on a 1440px laptop. 48px on a 1440px screen is 3.333vw.

Tips and best practices

  • Never use vw alone for font sizes; combine it with rem in clamp() so text still respects zoom settings.
  • Use 100dvh instead of 100vh for full-screen mobile sections.
  • vw includes the vertical scrollbar width on desktop, so 100vw can cause a small horizontal scroll; use 100% for full-width elements.
  • Percentages are relative to the parent element, not the screen; use them for widths inside containers.
  • Container query units (cqw, cqh) are like vw/vh but relative to a component’s container.

Frequently asked questions

How many pixels is 1vw?

1% of the viewport width. On a 1440px-wide window, 1vw = 14.4px.

What is the difference between vh and dvh?

vh is based on the largest possible viewport; dvh updates as mobile browser toolbars show and hide.
